# Plan Execution

## Purpose

Guide agents when carrying out an existing plan, design document, ticket, checklist, or explicit sequence of steps.

## Read When

Read this file when the human asks the agent to follow, execute, implement, continue, or finish an existing plan.

## Do Not Read When

Do not read this file when the plan is still being designed or debated.

## Operating Rules

When a plan exists, follow it through execution. Do not repeatedly stop for confirmation on each step.

Resolve small ambiguities using local context and engineering judgment.

Ask the human only when ambiguity changes the goal, risk, cost, user-visible behavior, security posture, or data-handling implications.

If the plan appears materially wrong, stop changing state and explain the mismatch.

If the work takes a long time, continue executing and provide occasional concise progress updates.

At the end, summarize what was completed, what was verified, and any remaining risks or follow-up items.
